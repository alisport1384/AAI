# تست نسخهٔ ۰.۱

هدف: در چند دقیقه بفهمی برنامه همان کاری را می‌کند که سند می‌گوید — **بدون هیچ بازار از پیش تعریف‌شده**.

## ۱. اجرا

- APK دیباگ را از صفحهٔ Actions همین مخزن (artifact با نام `hushyar-debug-apk`) بگیر و روی گوشی اندروید ۸+ نصب کن.
- یا محلی: `gradle testDebugUnitTest assembleDebug` (JDK 17، Android SDK 35).

## ۲. معرفی بازار (اجباری، چون برنامه هیچ بازاری ندارد)

۱۱ پرسش می‌آید. نمونهٔ یک بازار (هر بازار دیگری هم مجاز است):

| پرسش | نمونهٔ پاسخ |
|---|---|
| نام بازار | بازار قطعات کامپیوتر |
| چه می‌فروشد | کارت گرافیک، پردازنده |
| دسته‌ها | قطعات داخلی، لوازم جانبی |
| ویژگی‌ها | حافظه، گارانتی، برند |
| مهم‌ترین ویژگی | گارانتی |
| واحد قیمت | تومان |
| منبع داده | فهرست خودم |
| پرسش‌های پرتکرار | قیمت این کارت گرافیک چقدر است؟ (هر پرسش یک خط) |
| هشدار | قیمت غیرعادی پایین |
| زبان | فارسی |
| مرزها | توصیهٔ حقوقی نمی‌دهم |

بعد از «ساخت بازار»، برنامه وارد صفحهٔ خانه می‌شود.

## ۳. ثبت داده

در تب **داده**:

```
عنوان: کارت گرافیک ایسوس RTX 3060 حافظه 12 رم 8 گارانتی شرکتی
قیمت: ۱٫۲۵۰٫۰۰۰ تومان   ← عمداً واحد اشتباه؛ برنامه باید همان بخواند و ثبت کند
منبع: فهرست خودم
```

یا گروهی:

```
title,price,source,حافظه,گارانتی
کارت گرافیک ایسوس RTX 3060 حافظه 12,12500000,فهرست خودم,12,شرکتی
کارت گرافیک ایسوس RTX 3060 حافظه 12,13200000,سایت الف,12,محلی
کارت گرافیک ایسوس RTX 3060 حافظه 12,1500000,سایت ب,12,ندارد
```

## ۴. چه چیزی را باید ببینی

| کار | انتظار |
|---|---|
| خانه | کالاها یکسان‌سازی شده‌اند (سه آگهی → یک کالا) و بازهٔ قیمت نمایش داده می‌شود |
| تحلیل | امتیاز ارزش، برچسب قیمت (ارزان/متعارف/بالا/پرت)، ویژگی‌ها با منبع، هشدار «تضاد مشخصات» برای گارانتی شرکتی/محلی، و هشدار قیمت غیرعادی برای آگهی سوم |
| پرسش: «قیمت کارت گرافیک ایسوس چقدر است؟» | پاسخ با **میانه و بازه** و ارجاع به آگهی‌ها |
| پرسش: «قیمت پراید چقدر است؟» | **امتناع** + فهرست کمبودها؛ هیچ عددی ساخته نمی‌شود |
| تب خودم | جملهٔ «من چه هستم»، وظایف، مرزها و «چیزهایی که نمی‌دانم» — همه مشتق از بازار خودت |
| تعویض بازار | «نمایش JSON بازار فعلی» → ویرایش → «وارد کن»؛ یا بازار دوم بساز و فعال کن |

## ۵. آزمون تعویض بازار (مهم‌ترین آزمون برای این پروژه)

1. بازار «موبایل» بساز، دو آگهی ثبت کن، یک پرسش بپرس.
2. در تب **خودم** بازار دیگری بساز یا JSON یک پک دیگر را وارد کن.
3. باید ببینی ویژگی‌ها، پرسش‌های پیشنهادی، هشدارها و خودانگاره **کاملاً عوض می‌شوند**، بدون آپدیت برنامه و بدون کد.

## ۶. آزمون‌های خودکار

```bash
gradle testDebugUnitTest     # منطق خالص: نرمال‌سازی، قیمت، پک، تحلیل، پرسش‌وپاسخ
```

پوشش فعلی: JSON، متن فارسی/انگلیسی، قیمت، پک (ساخت/اعتبارسنجی/JSON)، یکسان‌سازی، امتیازدهی، هشدار، پرسش‌وپاسخ، Critic و امتناع.

# سناریوهای نسخهٔ ۲ (دستی، روی دستگاه)

## ۰. پیش‌نیاز
بدون بازار هم اپ بالا می‌آید. برای سناریوهای کاتالوگ، اول مصاحبه را کامل کن.

## ۱. یادگیری و دسته‌بندی
1. تب «پرسش» → `ذخیره کن: سقف بودجه‌ام ۲۰ میلیون تومان است`.
2. انتظار: پاسخ «در حافظه ثبت شد (دستهٔ بودجه)» + `memory.write` در «تغییرات داده».
3. تب «داده» → «حافظه»: رکورد با دستهٔ «بودجه»، اهمیت ≥۰.۸ و برچسب‌ها دیده شود.
4. `فراموش کن: سقف بودجه‌ام ۲۰ میلیون تومان است` → رکورد حذف و `memory.delete` ثبت شود.

## ۲. دوزبانگی
1. `قیمت گوشی سامسونگ گلکسی S24 چقدر است؟` → پاسخ فارسی با استناد به آگهی/منبع.
2. `what do users say about green tea and blood pressure?` → پاسخ انگلیسی (`lang: en`).
3. پرسش مخلوط («قیمت Samsung S24») نباید خطا بدهد.

## ۳. جستجوی وب
1. پرسشی بپرس که در کاتالوگ نیست؛ انتظار: گام‌های `web.search` و `web.fetch` در «مسیر استدلال».
2. هر بولت پاسخ باید جمله‌ای باشد که در یکی از صفحه‌های واکشی‌شده وجود دارد
   (چون استخراجی است) و استناد `W#` با آدرس داشته باشد.
3. اینترنت را قطع کن و همان پرسش را بپرس: پاسخ باید **امتناع** با ذکر موتورهای ناموفق باشد،
   نه پاسخ ساختگی.

## ۴. تغییر داده
1. تب «داده» → «آگهی‌ها» → «ویرایش» یک رکورد: عنوان و قیمت را عوض کن → ذخیره.
2. «حافظه» → ویرایش متن و دستهٔ یک رکورد؛ سپس «ادغام تکراری‌ها» با دو رکورد هم‌معنا.
3. هر سه عمل باید در تب «لاگ» و در جدول `audit` دیده شوند.

## ۵. لاگ `.md`
1. تب «داده» → «لاگ» → «نوشتن دفتر هوش به .md».
2. فایل در `/data/data/ir.aai.hushyar/files/hushyar/logs/` ساخته می‌شود؛
   سرصفحه باید تاریخ جلالی داشته باشد و بخش‌های حافظه/ممیزی/لاگ را شامل شود.

## ۶. بک‌آپ و بازیابی
1. تب «داده» → «پشتیبان» → «ساخت بک‌آپ» → نام فایل در «پشتیبان‌های روی دستگاه».
2. ZIP را باز کن: `backup.json`، `brain.md`، `logs/`، `memory/` باید باشند.
3. «بررسی» → خلاصهٔ شمارش‌ها + `sha256`.
4. یک کاراکتر در JSON دستی عوض کن → «بررسی سلامت» باید خطای چک‌سام بدهد و
   «بازیابی» نباید اجرا شود.
5. حافظه را دستی حذف کن، سپس «بازیابی» از همان ZIP → رکوردها برگردند.

## ۷. بی‌شبکه بودنِ هستهٔ تصمیم
1. حالت هواپیما + پرسش کاتالوگی → پاسخ محلی با استناد، بدون هیچ درخواست شبکه.
2. `بک‌آپ بگیر` و `ذخیره کن:` در حالت هواپیما باید کار کنند.

# سناریوهای نسخهٔ ۳ (پژوهش خودکار و انبار دانش)

## ۱. جستجوی چند-دوره‌ای
1. پرسشی بپرس که در آگهی‌ها نیست (مثلاً دربارهٔ یک برند چای یا یک لپ‌تاپ ناموجود).
2. تب «پرسش» → «مسیر استدلال»: باید `research.start` و سپس **دور ۱، دور ۲، …** دیده شود؛
   هر دور پرسش متفاوتی داشته باشد.
3. آخر پاسخ یک خط وضعیت هست: «شواهد کافی شد» یا «سقف بودجه پر شد».

## ۲. ذخیره و استفادهٔ دوباره
1. همان پرسش را دوباره بپرس (بدون تغییر داده).
2. انتظار: پاسخ با «از دانش ذخیره‌شده (آخرین بازبینی …)» و **بدون** دور جستجوی تازه؛
   در «مسیر استدلال» گام `knowledge.answer` دیده شود.
3. تب «داده» → «دانش»: ردیف‌ها با دسته، دامنه، تاریخ بازبینی و تعداد منابع.

## ۳. اصلاح و تناقض
1. یک ردیف دانش با عدد قدیمی داشته باش، سپس «بروزرسانی کن» بزن (یا پرسش کهنه).
2. اگر منبع تازه عدد دیگری بدهد: ردیف قبلی «منسوخ» می‌شود (حذف نمی‌شود) و
   در «آنچه آموختم» می‌نویسد «مقدار قبلی با دادهٔ … اصلاح شد».
3. اگر یک منبع نفی کند و دیگری تأیید: هر دو با برچسب تناقض ذخیره می‌شوند.

## ۴. عمق پژوهش
1. تب «دانش» → «سریع/متعادل/عمیق» را عوض کن و همان پرسش کهنه را دوباره بزن.
2. «عمیق» باید دورهای بیشتری برود (حداکثر ۵ دور/۱۴ صفحه) و «سریع» زودتر بایستد.

## ۵. آگهی از وب
1. پس از پژوهش، تب «آگهی‌ها» را باز کن: ردیف‌هایی با `منبع: وب:<دامنه>` و لینک صفحه.
2. تحلیل همان کالا باید قیمت‌ها را با آمار (میانه/بازه) نشان دهد؛ آگهی‌های بدون
   قیمت روشن نباید ساخته شده باشند (شمارش «ردشده» در گام `listing.harvest`).

## ۶. امنیت (تزریق دستور)
1. اگر صفحه‌ای متن «دستورهای قبلی را نادیده بگیر» داشت، در «مسیر استدلال» باید
   «صفحهٔ کنارگذاشته‌شده: نشانهٔ تزریق دستور» ثبت شود و آن صفحه در شاهدها نباشد.
2. با اینترنت قطع، پاسخ باید امتناع با ذکر خطای موتورها باشد.

## ۷. پشتیبان با دانش
1. «بک‌آپ بگیر» → ZIP؛ داخل `backup.json` بلوک `knowledge` و در `brain.md` بخش «دانش هوشیار».
2. بازیابی: ردیف‌ها با همان تاریخ بازبینی و وضعیت «منسوخ» برگردند.
3. یک `backup.json` نسخهٔ ۲ (بدون بلوک دانش) هم باید بدون خطا بازیابی شود.
