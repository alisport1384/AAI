# هوشیار ۰٫۱۵ — ارتقای مرحلهٔ عملی طبق سند L0–L9، بدون API پولی

این نسخه بر اساس **گزینهٔ انتخاب‌شدهٔ کاربر** ساخته شده است: اپ اندروید بدون سرور هم کار
می‌کند؛ یک سرویس سبک روی رایانه/سرور شخصی **اختیاری** است. «بدون هزینه» یعنی بدون اشتراک،
API پولی، GPU اجاره‌ای و سرویس ابری اجباری. رایانه، برق، ترافیک اینترنت و نگهداری شخصی
خودبه‌خود رایگان نمی‌شوند. سند پیوست برای MVP هم هزینهٔ GPU (~$400/mo) برآورد کرده بود؛
آن نسخهٔ سروریِ GPUدار با «هزینهٔ صفر» یکسان نیست و اینجا ادعای اجرای آن نمی‌شود.

## آنچه واقعاً پیاده شد

| لایهٔ سند | وضعیت این نسخهٔ عملی |
|---|---|
| L0 زیرساخت | فقط Python 3.10+ و SQLite FTS5 روی سخت‌افزار خودت؛ HTTPS برای اتصال شبکه، بدون Docker/K8s/GPU. |
| L1 مدل | مدل GGUF موجودِ **اختیاری روی گوشی** دست‌نخورده؛ سرویس سند از مدل استفاده نمی‌کند (`/health: model=none`). vLLM/70B روی گوشی یا سرور اجرا نشده. |
| L2 دروازه | مسیر صریح «از اسنادم:» به سرور، bearer token، محدودیت درخواست/حجم و عدم ثبت محتوا؛ گفتگوی عادی به سرویس شخصی ارسال نمی‌شود. بدون JWT چندکاربره و LangGraph. |
| L3 عامل | عامل/جستجوی مستند موجود روی گوشی؛ برای پرسش سند فقط نقل‌قول‌های واقعیِ همان رشته، نه خروجی LLM بی‌شاهد. |
| L4 دانش | نمایه‌سازیِ اختیاری فایل UTF-8 `txt/md/csv/html` تا ۱۰۰ KB، قطعه‌بندی و SQLite FTS5 با جداسازی بر اساس شناسهٔ گفتگو، نقل‌قول عین متن و شناسهٔ سند. **فقط جستجوی واژگانی**؛ بردار/embedding/PDF/OCR/GraphRAG ندارد. |
| L5 وب زنده | همان موتورهای جستجوی رایگان موجود در اپ؛ هیچ Tavily/Brave/Exa پولی اضافه نشده. پاسخِ «اسنادم» قیمت امروز را از سند قدیمی نمی‌سازد. |
| L6 محاسبه | دستور `حساب کن: 2^10 * sqrt(144)` روی گوشی با دستور زبان محدود و سقف پیچیدگی؛ **هیچ Python/کد دلخواهی اجرا نمی‌شود**. |
| L7 استدلال/بحث | شاهد و عدم‌قطعیت کنترل می‌شود؛ بحث سه‌عامله، Tree-of-Thought و تضمین استدلال عمیق پیاده نشده‌اند. |
| L8 حافظه/تکامل | گفتگوهای مستقلِ SQLite و دانش موجود حفظ شده‌اند؛ اسناد هر رشته روی سرور جدا هستند. وزن مدل به‌طور خودکار آموزش یا تغییر نمی‌کند. |
| L9 آزمون/حکمرانی | احراز هویت، TLS با pin گواهی و SAN میزبان، متریک شمارشی بدون متن پرسش، آزمون‌های HTTP/SQLite/استناد/جداسازی؛ درصدهای هدف سند بدون مجموعه‌داده و آزمایش واقعی **اندازه‌گیری نشده‌اند**. |

**مسیرهای صریح:** پرسش معمولی → مسیر فعلی اپ؛ `حساب کن:` → ماشین‌حسابِ روی گوشی؛
`از اسنادم:`/`docs:` → *فقط* سندهای همان گفتگوی منتخب روی سرور شخصی. مشکل اتصال یا
کمبود شاهد → پاسخ امتناع مستند، نه بازپخش قیمت کش‌شده یا حدس مدل. اپ برای عملکرد عادی
به اتصال سرور نیاز ندارد.

## راه‌اندازی رایگان سرور شخصی

پیش‌نیاز روی **رایانهٔ خودت**: Python 3.10+ با SQLite FTS5، OpenSSL، دسترسی گوشی و رایانه
به یک شبکهٔ مورد اعتماد. از ریشهٔ پروژه (`AAI/`) اجرا کن:

```bash
python3 -m unittest selfhost.test_hushyar_backend -v
# یک IP ثابتِ شبکهٔ داخلیِ رایانه را جایگزین کن؛ نمونه:
LAN_IP=192.168.1.10
umask 077
mkdir -p "$HOME/.config/hushyar" "$HOME/.local/share/hushyar"
openssl rand -hex 32 > "$HOME/.config/hushyar/token"
openssl req -x509 -newkey rsa:3072 -nodes -sha256 -days 365 \
  -subj "/CN=$LAN_IP" -addext "subjectAltName=IP:$LAN_IP" \
  -keyout "$HOME/.config/hushyar/key.pem" -out "$HOME/.config/hushyar/cert.pem"
chmod 600 "$HOME/.config/hushyar/token" "$HOME/.config/hushyar/key.pem"
openssl x509 -in "$HOME/.config/hushyar/cert.pem" -outform DER | sha256sum
# خروجی خط قبل: ۶۴ کاراکتر اول = اثر انگشت گواهی برای کادر اندروید.
export HUSHYAR_BACKEND_TOKEN="$(cat "$HOME/.config/hushyar/token")"
python3 -m selfhost.hushyar_backend serve \
  --db "$HOME/.local/share/hushyar/personal.sqlite3" \
  --host 0.0.0.0 --port 8765 \
  --cert "$HOME/.config/hushyar/cert.pem" --key "$HOME/.config/hushyar/key.pem"
```

برای آزمایش از همان رایانه:

```bash
curl --cacert "$HOME/.config/hushyar/cert.pem" \
  -H "Authorization: Bearer $HUSHYAR_BACKEND_TOKEN" \
  "https://$LAN_IP:8765/health"
# انتظار: schema=hushyar.docs/1, retrieval=sqlite-fts5, model=none
```

گوشی و رایانه باید روی شبکهٔ قابل دسترس هم باشند؛ در **تب «بک‌اند»** اپ نشانی
`https://192.168.1.10:8765`، اثر انگشت SHA-256 گواهی و محتوای فایل `token` را ثبت کن،
بعد «آزمون اتصال» بزن. برای گواهیِ خودامضا، اثر انگشتِ گواهیِ DER (نه کلید عمومی) باید
دقیقاً برابر باشد و SAN گواهی باید با **همان IP یا نام** واردشده جور درآید. اگر IP/گواهی
عوض شد، pin را دوباره ثبت کن. بدون TLS سرور فقط اجازهٔ گوش‌دادن روی `127.0.0.1` دارد؛
**درگاه را در اینترنت عمومی باز نکن** و فایروال را به شبکهٔ شخصی محدود کن. رمزِ نمونه یا
فایل کلید را در Git نگذار؛ اگر کلید/گواهی/توکن افشا شد، آنها را عوض کن.

کلید اتصال به‌صورت رمزگذاری‌شده با Android Keystore در حافظهٔ خصوصی گوشی می‌ماند و به
`backup.json` نمی‌رود. بک‌اندِ اختیاری سرور داده‌ای از اپ را **خودکار** دریافت نمی‌کند:
هنگام نمایه‌سازی، متن فایل انتخاب‌شده؛ هنگام پرسشِ صریح، فقط متن همان پرسش؛ و برای
فهرست/حذف، شناسهٔ گفتگو/سند همراه با کلید احراز هویت از طریق HTTPS منتقل می‌شوند.
تاریخچهٔ کامل گفتگو و فایل‌های انتخاب‌نشده فرستاده نمی‌شوند. جستجوی وب عمومیِ پیشینِ اپ
همچنان برای پرسش‌های معمولی وجود دارد؛ این سرویس آن را جایگزین نمی‌کند و به اینترنت
یا API دیگری درخواست نمی‌فرستد.

## استفاده، حذف و پشتیبان

1. در «پرسش»، یک گفتگوی مشخص انتخاب کن. در «بک‌اند»، فایل متن کوچک را با
   «انتخاب و ارسال فایل متنی به سرور شخصی» انتخاب کن؛ PDF و فایل باینری رد می‌شوند.
2. در **همان** گفتگو بپرس: `از اسنادم: وزن نبشی ۴ چیست؟` پاسخ فقط نقل‌قول‌های یافت‌شده و
   شناسه/نام سند دارد؛ ادعای «جواب قطعی» یا صحت منبع خارجی نمی‌کند. در گفتگوی دیگر با
   همان سؤال، سندِ گفتگوی اول دیده نمی‌شود.
3. `از اسنادم: قیمت نبشی ۴ امروز چقدر است؟` یا «قیمت روز/نرخ فعلی» باید امتناع کند؛
   برای وب زنده، بدون پیشوند سند سؤال کن. `حساب کن: 2^10 * sqrt(144)` نتیجهٔ
   **محاسبه، نه قیمت روز** می‌دهد.
4. اگر سرور خاموش باشد، گفتگوی عادی کار می‌کند؛ پرسشِ صریحِ سند پیام خطای منبع نشان می‌دهد.
   عنوان، انتخاب و تاریخچهٔ گفتگوی محلی مثل ۰٫۱۴ در SQLite می‌مانند.
5. دکمهٔ «حذف از سرور» یک سند، و «پاک‌کردن اسناد همین گفتگو» همهٔ اسناد همان رشته را از
   سرور حذف می‌کند. **حذف گفتگو یا قطع اتصال روی گوشی خودبه‌خود سرور را پاک نمی‌کند**؛
   بهتر است پیش از حذف گفتگو اسناد آن را از تب بک‌اند پاک کنی. «بازنشانی کامل» روی گوشی
   فقط داده‌های گوشی و کلید اتصال را پاک می‌کند، نه فایل SQLite رایانه.

بک‌آپِ اپ (`hushyar.backup/5`) گفتگوهای گوشی را دارد اما **نه فایل‌های سندِ سرور و نه
توکن** را. **متن پرسش‌ها و نقل‌قول‌هایی که در پاسخ گفتگو دیده‌ای در تاریخچه و بک‌آپ گوشی
هم هستند**؛ آن ZIP را نیز محرمانه نگه‌دار. برای بک‌آپ سازگار و جایگزینی اتمیکِ جداگانهٔ
اسناد سرور:

```bash
python3 -m selfhost.hushyar_backend backup \
  --db "$HOME/.local/share/hushyar/personal.sqlite3" \
  --out "$HOME/.local/share/hushyar/personal-backup.sqlite3"
```

فایل SQLite پشتیبان **متن اصلی اسناد را آشکار دارد**: فقط در محل خصوصی نگه‌دار؛ سرویس
فایل پایگاه و پشتیبان تازه را با سطح دسترسی `0600` می‌سازد/اصلاح می‌کند و اگر مسیر
`--db` پشتیبان اشتباه باشد، به‌جای ساخت فایل خالی خطا می‌دهد. این **رمزگذاری دیسک نیست**.
برای بازیابی، سرویس را متوقف کن و فایل پشتیبان را جایگزین پایگاه دادهٔ سرور کن. حذف
سند در رابط، آن را از فهرست و جستجو حذف می‌کند، اما **پاک‌شدن فیزیکیِ بیت‌ها** از صفحات
آزاد SQLite یا بک‌آپ‌های قدیمی را تضمین نمی‌کند. پاک‌کردنِ قطعیِ همهٔ اسناد سرور نیاز
به حذف/نگه‌نداشتن تمام نسخه‌های این پایگاه و بک‌آپ‌های آن دارد.

## قرارداد و امنیت سرویس

فقط این مسیرها وجود دارند (همه با `Authorization: Bearer ...`):

| درخواست | کاربرد |
|---|---|
| `GET /health` | نسخه و موتور جستجوی در دسترس، بدون فاش‌کردن اسناد |
| `POST /v1/documents` | `thread_id`, `title`, `text`, `kind`؛ نمایه‌سازی صریح |
| `GET /v1/documents?thread_id=...` | فهرست همان رشته |
| `POST /v1/query` | `thread_id`, `question`؛ حداکثر ۵ نقل‌قولِ عین سند یا امتناع |
| `DELETE /v1/documents/{id}?thread_id=...` | حذف سند همان رشته |
| `DELETE /v1/threads/{id}/documents` | حذف همهٔ اسناد همان رشته |
| `GET /metrics` | شمار درخواست/خطا/امتناع و P95، **بدون متن سؤال/فایل/توکن** |

پاسخ اسناد با `schema: hushyar.docs/1`، `refused`، `text`، `bullets` و
`citations[{ref,label,url:null,quote}]` است. سرور نقل‌قول را از قطعهٔ ذخیره‌شده می‌گیرد؛
اپ نیز تعداد/شکل/طول استناد را کنترل می‌کند، ادعای عددیِ خارج از نقل‌قول در متن پاسخ را
رد می‌کند و هیچ URL ساختگی به نقل‌قول سند نمی‌افزاید. جستجو **واژگانی** است؛ ممکن است
نتیجه‌ای مرتبط را از دست بدهد، ولی عدد/سایز اشتباه را با عنوانِ پاسخ قطعی نمایش نمی‌دهد.
ورودی‌ها و خروجی‌ها سقف اندازه دارند؛ SQL با پارامتر فرستاده می‌شود؛ کد دلخواه یا متن دستور
موجود در سند اجرا نمی‌شود. این سرور **تک‌مالک** است، نه محیط چندکاربرهٔ اینترنتی؛
JWT/RLS/رمزگذاریِ دیسک و ممیزیِ پروداکشن سند کامل هنوز پیاده نشده‌اند.

## آزمون، فایل نصب و مرز ادعا

اجرای محلی `python3 -m unittest selfhost.test_hushyar_backend -v`: **۱۲ آزمون موفق**
با HTTP واقعی روی localhost، SQLite FTS5، نقل‌قول، حذف، بک‌آپ، جداسازی گفتگو، قیمتِ
کهنه و TLS خودامضا. اجرای `:app:testDebugUnitTest :app:assembleDebug` با JDK 17:
**۴۹۹ آزمون Android/JVM در ۳۸ مجموعه، صفر شکست/خطا/ردشده، APK ساخته شد**. آزمون‌های
Android شامل گفتگو/مهاجرت/بک‌آپ، حسابگر، قرارداد استناد و اتصال TLS با سوکت JVM هستند؛
pin نادرست و SAN نامنطبق در آزمون سوکت رد شدند. این آزمون JVM جای آزمون روی گوشی نیست.

APK دیباگ `hushyar-0.15.0-debug.apk` با شناسهٔ `ir.aai.hushyar`، کد نسخهٔ `22` و
حداقل Android 8 (`minSdk=26`) ساخته شد. امضای آن با `apksigner` بررسی شد. SHA-256 فایل:

```text
0c7ccf52aa147e7e0c90d490ce5b4e4c47cceae98b73ab769abf0de2cba48cc1
```

اثر انگشت گواهی امضای APK: `4c3abdcdec1a090d76f9f5b4b54155f1e384e81b58278a82bb1e7efdd393c82c`؛
**این گواهی با APK محلیِ ۰٫۱۴ برابر است**، پس ارتقای درجا از فایل ۰٫۱۴ با حفظ
داده *از نظر امضا* ممکن است، اما این ارتقا روی گوشی آزمایش نشده. APKهای ۰٫۱۲ تا ۰٫۱۴
برای کاهش فضای کاری، با SHA-256 تأیید و در `hushyar-legacy-0.12-to-0.14.tar.xz`
بایگانی شده‌اند؛ برای نصب دوباره باید فایل موردنظر را از آن استخراج کنی. امضای APK
قدیمیِ ۰٫۱۳ با ۰٫۱۵ فرق دارد؛ **نسخهٔ ۰٫۱۳ را قبل از تهیهٔ پشتیبانِ قابل‌دسترسی بیرون اپ حذف نکن** و
راهنمای `docs/V14-CHAT.md` را بخوان. برای ساخت نسخه‌های بعدی با همان امضا، کلید امضای
محلی باید محرمانه و پایدار نگه داشته شود؛ APKهای CI معمولاً کلید دیباگ دیگری دارند.

اجرای دستی روی گوشی، اتصال TLS از Android واقعی به رایانهٔ شخصی، صحت/دسترس‌پذیری
جستجوی زندهٔ وب و ادعاهای عددی عملکرد/دقتِ سند L0–L9 **در این محیط انجام/اثبات نشده‌اند**.
