# معماری هوشیار (v0.15)

یک نگاه از بالا، تا کسی که تازه وارد می‌شود بداند هر فایل چه کاری می‌کند و کدام «قاعدهٔ سخت» را
نباید بشکند.

```
پرسش کاربر
   │
   ├─ AppViewModel.ask → SQLite: ذخیرهٔ پیام کاربر در رشتهٔ منتخب
   │    ├─ ConversationContext.resolve(فقط پیام‌های همین رشته) → پرسش مستقل یا پرسش روشن‌کننده
   │    ├─ «من فروشگاه … هستم»  → DomainSetup → بستهٔ دانش سفارشی در preference
   │    ├─ اگر پرسش قیمت + نشانی دارد: تصمیم قطعیِ «اول خودِ نشانی‌ها» (نه مدل/مطالعهٔ جدا)
   │    ├─ وگرنه LocalPlanner.decide → مدل محلی (اگر نصب و روشن) یا قاعدهٔ ثابت
   │    │        کارها: دانش / جستجو / یادگیری / گفتگو / روشن‌سازی
   │    └─ Agent.run
   │         ├─ 0.5 نشانی‌های داده‌شده → HTML خام → پست/ردیف → قیمتِ شاهددار
   │         ├─ 1  دستور داده (ذخیره/فراموش/بک‌آپ/تحقیق …)
   │         ├─ تازه‌سازی صریح → واکشی پیوند یا پژوهش با دانشِ قبلیِ کنارگذاشته‌شده
   │         ├─ 2  کاتالوگ آگهی‌های خودت (آفلاین، دقیق)
   │         ├─ 2.1 قیمتِ تازهٔ همین کالا/سایز از دانش منبعیِ محلی
   │         ├─ 2.5 MaterialBrain   — فلزات: جدول استاندارد + فرمول + قیمت
   │         ├─ 2.6 AnyDomainBrain  — هر کالای دیگر: بستهٔ دانش + دانش نوع‌دار + یکاها
   │         ├─ 3  حافظهٔ کاربر
   │         ├─ 3.5 پروندهٔ پاسخ قبلی (فقط با تطابق دقیق موضوع و کالا)
   │         ├─ 4  دانش ذخیره‌شده
   │         └─ 5  پژوهش خودکار (SearchCore → DeepResearcher → Critic)
   │
   └─ پاسخ: متن + بولت + منبع + فرمول + تاریخ + آنچه یاد گرفت
```

## قاعده‌های سختی که نباید شکسته شوند

1. **هیچ عددی از مدل زبانی نمی‌آید.** مدل می‌تواند انتخاب کند، پیشنهاد بدهد و از متن استخراج
   کند؛ عددِ نهایی یا از جدول/دانش است یا از محاسبه‌ای که فرمولش چاپ می‌شود، یا از متنی که عددش
   در همان متن دیده شده است.
2. **هر پاسخ باید بتواند منبعش را نشان دهد**؛ اگر نتواند، «نمی‌دانم» می‌گوید.
3. **حدس، دانش نیست.** سایز نامعلوم، بستهٔ بی‌اندازه، قیمتِ کهنه — همه صریح اعلام می‌شوند.
4. **حافظه و دانش** در SQLite می‌مانند و در پشتیبان می‌آیند؛ مدل در APK نیست.
5. **شبکه فقط جایی که کاربر می‌بیند**: جستجوی موتورها، واکشی صفحه‌های همان نتایج. بدون حساب،
   بدون کلید، بدون واسطه.

## ۹. لایهٔ جستجو (v0.12)

```
پرسش
  └─ QuestionReader / FrameParser → عبارت جستجو
        └─ SearchCore.search
              ├─ منابع کاربر (EngineKind.USER)   ← اول از همه
              ├─ Google  (HTML با udm=14، و خوراک گوگل‌نیوز)
              ├─ Bing    (HTML با mkt=fa-IR، و RSS همان جستجو)
              ├─ ویکی‌پدیا (API JSON) ، Mwmbl (JSON) ، Dogpile ، Swisscows ، DDG ، Seznam
              └─ دم‌بلند: موتورهای جاوااسکریپتی/بسته (یک بار امتحان، بعد استراحت پله‌ای)

هر پاسخ موتور: SerpOutcome = RESULTS | EMPTY | BLOCKED | RATE_LIMITED | JS_REQUIRED | HTTP_ERROR | NETWORK
```

**قاعده‌های ثابت این لایه**

1. **بدون کلید، بدون حساب، بدون واسطه.** هر نشانی عمومی است.
2. **بدون جعل هویت**: UA همان UA صادق اپ است؛ ۴۰۳/۴۲۹ باعث پروکسی یا تغییر UA نمی‌شود، فقط
   استراحت پله‌ای (۴۵ ثانیه تا ۱۰ دقیقه) و گزارش صادقانه.
3. **`mkt`/`hl`/`gl` بخشی از قالب‌اند**، نه جزئیات تزئینی: اندازه‌گیری نشان داد نبودِ `mkt`
   یعنی «صفر نتیجه» از Bing.
4. **هر لینک پیش از پذیرش باز می‌شود** (`unwrapLink`): DuckDuckGo `uddg=`، Google `q=`،
   Bing `u=a1<base64url>`، Seznam `redir=`.
5. **تجزیه بلوکی مقدم بر تجزیهٔ لنگری است**: اگر موتور نتیجه‌ها را گروه‌بندی می‌کند، عنوان و
   جملهٔ همان گروه خوانده می‌شود.
6. **صفر نتیجه یک پاسخ نیست**: هر موتور با `SerpOutcome` گزارش می‌شود و «پویش موتورها» همان
   جدول را روی شبکهٔ کاربر نشان می‌دهد.

## ۱۰. صفحهٔ بک‌اند (v0.12)

سه متن آزاد — هدف، محیط، پرامپت کلی — در تنظیمات ذخیره می‌شوند و پیش از قاعده‌های ثابت به مدل
می‌رسند (`LocalPrompt.systemWithDirective`). قاعده‌های شاهد و عدد **بعد** از آن می‌آیند و با
هیچ پرامپتی قابل حذف نیستند. منابع جستجو (`search.sources`) و کلید لاگ (`log.enabled`) هم در
همین صفحه‌اند؛ لاگ پیش‌فرض خاموش است. از ۰٫۱۳، علاوه بر ممیزی، رویدادها و فایلِ خودکارِ
پرسش‌وپاسخ هم فقط با روشن‌کردن همین کلید نوشته می‌شوند؛ ثبت دانش مستقل می‌ماند.

## ۱۱. نشانیِ داخل پرسش (v0.13)

برای **پرسش قیمت** با نشانی، موتور عمومی جستجو نمی‌شود: `UrlIngest.links` نشانی‌ها را از متن
کالا و اندازه جدا می‌کند، `SearchCore.fetchRaw` HTML را می‌آورد، پست‌های تلگرام و ردیف‌های جدول
شبکه‌ای مستقل می‌شوند، سپس مبلغ با `PriceParser` از **عدد قیمت** خوانده می‌شود، نه از سایز یا
وزن. پس از همهٔ نشانی‌های داده‌شده، در صورت نبود عدد یک پیوندِ هم‌دامنه و مرتبط نیز باز می‌شود.
گام‌های هر واکشی در باکس «داخل هوش چه گذشت؟» دیده می‌شوند؛ در حالت لاگ خاموش فقط روی صفحه‌اند.
قیمت‌های معتبر با کلیدِ گونهٔ محصول، منبع و عمر سه‌روزه ذخیره می‌شوند. جزئیات، نمونه‌ها و
محدودیت‌ها در `docs/V13-USER-SOURCES.md`.

## ۱۲. گفت‌وگوی چندنوبتی (v0.14)

`chat_thread` نام و زمان هر رشته را نگه می‌دارد؛ `chat_turn` متنِ اصلی کاربر، پرسشِ
حل‌شده، پاسخِ کاملِ منبع‌دار یا وضعیت ناتمام را دارد. کلید خارجیِ حذف آبشاری مانعِ
باقی‌ماندن پیامِ یتیم است. انتخاب رشته در preference می‌ماند و بعد از بستن اپ باز می‌شود.
دادهٔ نسخهٔ ۵ بدون حذف جدول یا مدل ازپیش‌دانلودشده به شِمای ۶ می‌رسد، **اگر APK با همان
امضا درجا نصب شود**.

`AppViewModel.ask` پیام را پیش از انجام پژوهش ذخیره می‌کند، فقط پیام‌های کاملِ همان رشته
را به `ConversationContext` می‌دهد و بعد پرسشِ حل‌شده را به `LocalPlanner` و `Agent` می‌فرستد.
زمینهٔ مدل محدود است و خروجی بازنویسی با اعداد/واژه‌های پرسش‌های خودِ کاربر و مرجعِ همان
رشته کنترل می‌شود. «منبعش؟» به استنادِ ثبت‌شدهٔ پاسخ قبلی اشاره می‌کند، نه به نتیجهٔ جدید؛
«به‌روزش کن» بازخوانی نشانی یا جستجوی تازه را تحمیل می‌کند. نبودِ مرجع روشن → پرسش
روشن‌کننده، نه پاسخ حدسی. دانشِ معتبر برنامه همچنان میان گفتگوها مشترک است و هر عددِ
پاسخ باید از مسیر شاهد یا محاسبهٔ پیشین بیاید؛ **گفتگوی قبلی شاهد قیمت روز نیست**.

پشتیبان نسخهٔ ۵ هر دو جدول و انتخاب رشته را دارد، بازیابی پیامِ یتیم را رد می‌کند و
بازنشانی کامل هر دو را پاک می‌کند. صدور ZIP به محل انتخاب‌شدهٔ کاربر از تب پشتیبان انجام
می‌شود؛ مدل GGUF جداگانه صادر می‌شود. محدودیت امضای نسخهٔ ۰٫۱۳ قبلی و مسیر جایگزین در
`docs/V14-CHAT.md` آمده است.

## ۱۳. بک‌اند شخصیِ اختیاری و ابزار حساب (v0.15)

```
AppViewModel.ask (پیامِ همان رشته ابتدا در SQLite گوشی ثبت می‌شود)
  ├─ «حساب کن:» → SafeCalculator → پاسخ محلی با trace، بدون اجرای کد
  ├─ «از اسنادم:» → PrivateBackendSettings (Keystore token)
  │                  → PinnedHttpsTransport (HTTPS + SHA-256 pin + SAN)
  │                  → selfhost (Bearer + limit + SQLite FTS5 scope=thread_id)
  │                  → فقط نقل‌قولِ عین chunk + citation doc-id، یا امتناع
  └─ پرسش معمولی → مسیر قبلیِ ConversationContext / LocalPlanner / Agent
```

دستورهای ویژه قبل از حل ارجاع به‌طور **صریح** تشخیص داده می‌شوند؛ نه مدل و نه متن وب
حق فعال‌کردن ابزار حساب یا ارسال اسناد را ندارند. تاریخچهٔ رشته به سرور شخصی فرستاده
نمی‌شود؛ فقط متن پرسشِ `از اسنادم:` و فایلِ انتخاب‌شده از SAF می‌روند. توکن داخل
`backup.json` نیست و با Android Keystore در SharedPreferences خصوصی رمز می‌شود؛ فایل‌های
سرور هم جزو پشتیبان گوشی نیستند. حذف رشتهٔ گوشی به‌معنی حذف اسناد سرور نیست؛ UI هشدار و
مسیر پاک‌سازی صریحِ سرور را دارد. نبود سرور یا نبود شاهد، پاسخ حدسی را فعال نمی‌کند.

سرویس Python فقط متن/HTML کوچک را تجزیه و در SQLite FTS5 نمایه می‌کند؛ embedding/مدل
زبان/جستجوی وب/اجرای Python دلخواه ندارد. API دارای اندازه/نرخ محدود، TLS برای شبکه،
Bearer token و متریک بدون متن پرسش است. سندِ اصلی L0–L9 یک هدف بزرگ‌تر و پرهزینه‌تر است؛
وضعیت دقیق هر لایه و آزمون‌ها در `docs/V15-HYBRID.md` آمده‌اند.
