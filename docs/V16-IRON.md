- **فرمول‌ها:** میلگرد `d²/162`، ورق `b×t×7850/1e6`، لوله `πt(D-t)7850/1e6`، قوطی `BH-(B-2t)(H-2t)`، نبشی `t(a+b-t)`، تیر/ناودانی/سپری جدول اولویت دارد.

## 2) دیتابیس آفلاین Qwen-فهم

### معماری RAG انتخاب‌شده (با قید RAM گوشی)
- **دسکتاپ (مرجع):** PyMuPDF → BGE-M3 (560M, 1024d, 8192ctx) → FAISS (cosine) → Qwen3-0.6B via llama.cpp (temp 0.7 top_p 0.8 top_k 20؛ thinking: 0.6/0.95/1.5).
- **روی گوشی (فعلی — سازگار با اپ):** `Html.mainText` → `QwenRag.chunk` (450 توکن ≈ 900 حرف، overlap 140 حرف، جمله‌محور) → `KnowledgeItem` در SQLite (جدول `knowledge`) → بازیابی لغوی امتیازی `KnowledgeBank.answerable` (topicMatch 0.45 + claimRelevance 0.30 + freshness 0.15 + confidence 0.10).
- **چرا بدون FAISS؟** اپ فعلاً Embedding/FAISS ندارد؛ بازیابی لغوی فعلی تست‌شده و آفلاین است. ارتقا: `sqlite-vec` یا `Chroma` + `multilingual-e5-small` (23MB INT8) — فرمت چانک بدون تغییر می‌ماند، فقط scorer یک جملهٔ cosine می‌گیرد.

### فرمت ذخیره (Qwen می‌فهمد)
هر `IronCategory` → 10-12 `KnowledgeItem` (claim ≤ 240 حرف برای نمایش + متن کامل چانک در tags) با فیلدها:
`topic="آهن‌آلات X"`, `question="X چیست/مشخصات/کاربرد/معامله/مالیات"`, `claim=جملهٔ آموزنده`, `category="iron"`, `attribute=نام فارسی`, `layer=basics/specs/trade/usage/tax`, `tags=[شکل, جنس, واحد...]`, `url=asset://iron_knowledge/x`, `domain=ironpin`, `confidence=0.92`, `ttlDays=180`.

تحقیق وب → `QwenRag.toKnowledgeItems(page)` → چانک‌های `rag` با `tags=[rag, chunk:i/n, tok:450]`. هر دو مسیر با `repos.knowledgeUpsert` ذخیره و با `knowledgeAnswerable` خوانده می‌شوند؛ مدل فقط بازنویسی می‌کند (Grounding جلوی عددسازی).

### فایل‌ها
- `domain/IronKnowledge.kt` — ۱۸ خانواده + `toKnowledgeItems()`
- `domain/IronSeed.kt` — سید یک‌باره (`PREF_SEEDED`), قابل بازنصب
- `domain/QwenRag.kt` — چانکر Qwen (450tok/overlap، تخمین توکن fa)
- `domain/DeepStudy.kt` — حلقه تحقیق: هر صفحه → جملات + چانک‌های rag (بخش وحشتناک مهم)
- `data/Data.kt` — SQLite knowledge (نسخه ۶، TTL 45 روز پیش‌فرض، iron 180 روز)
- `AppViewModel.kt:seedIronKnowledge/reseedIronKnowledge` — دکمه‌های تب دانش + سید خودکار در `init`

## 3) سه تب

### پرسش (`ui/AskScreen.kt`)
- ویندو کانتنت (آخرین پرسش + تعداد پیام)
- فیلد پرسش + حالت تفکر (سریع/متعادل/عمیق → `researchDepth` quick/balanced/deep)
- تاریخچهٔ چتِ ماندگار (thread جدا)، تصمیم و گام‌ها، استناد

### دانش (`ui/KnowledgeScreen.kt`)
- آمار IronPin + خلاصهٔ Knowledge
- کارت «دیتابیس آفلاین» — بارگذاری/بازنصب (۱۸ خانواده)
- **تحقیق موضوعی** — یک موضوع بده → `tools.deepStudy(topic)` با **همهٔ موتورها** (گوگل/ddg/بینگ/mwmbl/.../گردو/ذره‌بین + منابع کاربری) تا اشباع؛ لایه‌ها basics/specs/price/reviews/updates/sources؛ خروجی به دانشِ Qwen-فهم
- بک‌آپ تمام دانش (ZIP + Markdown) + بروزرسانی کهنه‌ها

### تنظیمات (`ui/SettingsScreen.kt`)
- **لاگ حرفه‌ای** پیش‌فرض خاموش، Switch + ذخیره .md (`exportLogMarkdown`)
- **مدل:** انتخاب از `ModelCatalog.all` (qwen2.5 0.5B/1.5B, qwen3 0.6B/1.7B, gemma-3 270M/1B, llama 1B/3B)، دانلود/resume+SHA256، بارگذاری در RAM، ذخیره/بارگذاری از فایل، تست مدل
- **تنظیمات مدل (تحقیق‌شده):** Qwen3 sampling (non-thinking temp0.7 top_p0.8 top_k20؛ thinking 0.6/0.95/1.5), context 2048-4096 روی گوشی، threads = cores∩[1,4]; `directModel` (محاسبه/گفتگوی مستقیم)
- **موتورها:** 30 موتور (28 قبلی + گردو + ذره‌بین)، آزمون سلامت، افزودن دیتابیس شخصی (`UserSource` → EngineSpec با friction 0)
- **بک‌اند شخصی اختیاری** + تنظیمات عمومی + پاک‌سازی کامل

## 6) آزمون دستیِ پیشنهادی پس از نصب

1. دانش → بارگذاری دیتابیس آفلاین → باید «~200+ نکته» بگوید؛ پرسش «میلگرد A3 چیست؟» باید بدون اینترنت جواب بدهد.
2. دانش → تحقیق موضوعی «قیمت ورق گالوانیزه 0.5» → باید موتورها را بشمرد و پوشش 80%+ بدهد.
3. تنظیمات → آزمون سلامت موتورها → گردو/ذره‌بین باید در لیست باشند.
4. تنظیمات → لاگ روشن → پرسش → لاگ باید Markdown ذخیره کند.
5. دانش → بک‌آپ ZIP → باید شامل knowledge + threads باشد و قابل بازیابی باشد.
